# 附加题：初始重叠 / 初始居中 开局

对应站点开关：`#overlap-toggle`（初始重叠）、`#center-toggle`（初始居中），
在普通页（不带 `?mode=exam`）可选，考核模式下这两个开关是灰的。

单独运行入口：`solver/run_overlap.py`

```bash
python solver/run_overlap.py --mode overlap    # 初始重叠
python solver/run_overlap.py --mode center     # 初始居中
python solver/run_overlap.py --mode overlap --headful --video ./vid --shots ./shots
```

---

## 一、为什么不能用主流程的做法

主流程（`run_exam.py`）的前提是：30 块拼图各自躺在**托盘槽位**上，按槽位切图就能
稳定拿到每一块。

这两种开局把块**堆起来**：

- 重叠模式：堆在棋盘左右两条边带，每边约 15 块
- 居中模式：堆在棋盘范围内

实测堆叠很密，**大量块只露出一角甚至完全被压住**。这带来两个问题：

1. **逐格模板匹配连"位置"都不可信**：被压住的块，匹配到的高分位置往往落在
   盖在它上面的那块上。
2. **抓取会抓错人**：就算位置对了，从矩形中心按下去，抓住的是压在上面的块。

早期版本（按格子逐个匹配 + 拖拽）实测只到 **8/25**，且会越拖越乱。

---

## 二、现在的做法：先摊开，再识别

```
抓一块 → 拖到空闲暂存区 → 它完整露出来 → 模板匹配认出它是哪一格 → 拖回自己的格子
```

具体流程：

1. **找可抓的块**：对堆叠区做**距离变换**，取离边缘最远的点（一定能命中块内部）。
   按下后小幅移动，比较像素变化，确认真的抓住了块才继续 —— 因为游戏是按
   **块轮廓**做命中判定的，抓在透明角、投影、缝隙上时整块纹丝不动。
2. **拖到暂存区**：重叠模式用空棋盘中央，居中模式用空的左侧边带。
3. **识别**：块此刻完整可见，对 20 个照片格模板在暂存点附近做匹配，取最高分。
4. **归位**：从块**真实中心**抓到对应格心，偏移为 0。能吸附就吸附；
   暂不满足锚点条件就先放在格子上。
5. **补吸附**：对"放在格子上但没吸附"的块，按从外到内重新拿起放下一次。
6. **纯白块**：没有纹理，模板识别不出来，按白色连通域定位 + 排除法试放。

## 三、实测结果（如实记录）

| 版本 | 做法 | 结果 | 用时 |
|---|---|---|---|
| v1 | 逐格模板匹配 + 中心抓取 | 8/25 | 39s |
| v2 | 加搜索区域限制 + 失败原路拖回 | 7/25 | 16s |
| v3 | 加"可见区域抓取点" | 6/25 | 91s |
| v4 | 暂存台识别（盲目铺点） | 14/25 | 65s |
| v5 | 暂存台识别 + 距离变换选点 | **17/25** | 457s |
| v6 | v5 + 白块轮换 | 14/25 | 388s |

**结论：附加题目前是部分可用，没有做到稳定通关。**

失败构成（从最终画面核对）：

- 约 12–17 块能正确识别并整齐归位
- 剩余块仍散在堆里，或压在格子上没吸附
- 纯白块最不稳定：试放靠排除法，5 个白格常常只填上 1–2 个

## 四、已知难点

| 难点 | 说明 |
|---|---|
| 完全遮挡 | 堆里有些块被完整盖住，只能靠"移走上面的"逐层剥离，顺序敏感 |
| 抓取命中 | 游戏按块轮廓判定，落点必须真的在块身上；投影、透明角、缝隙都不算 |
| 白块歧义 | 5 个白块形状相近但互不通用，只能试放；试放失败还要原路拖回，否则场面更乱 |
| 时间成本 | 每块要走"抓→暂存→识别→归位"4 步，单局 6–8 分钟 |
| 方差大 | 同参数两次跑出 17/25 和 14/25，取决于堆叠密度和白色格子的位置 |

---

## 五、如果继续做，下一步

1. **白块用形状求解**：白块是纯白剪影，四边齿型（凸/凹/直）可以精确读出；
   再由"相邻白格齿型必须互补 + 边界格必须直边"建约束，解出唯一对应，
   替代现在的试放。
2. **暂存台改多格**：一次摊开 4–6 块而不是 1 块，减少往返拖拽次数。
3. **记录已归位块的位置**，避免重复识别和重复拖拽。
